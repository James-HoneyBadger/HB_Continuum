# Local AI summarization

HB Continuum can summarize messages and conversations using a **locally
running** Ollama instance. AI is strictly opt-in and disabled by default.
Summaries are derived, replaceable information — never evidence, never part
of the original record.

## Opt-in gate

No network request is made unless **both** preferences hold:

- `ai.enabled` is `true`.
- `ai.backend` is `ollama`.

Set these in the desktop **Preferences** workspace (AI group) or by editing
`preferences.json`. The default is `ai.enabled=false` and `ai.backend=none`.

| Preference | Default | Meaning |
|---|---|---|
| `ai_enabled` | `false` | Master opt-in switch |
| `ai_backend` | `none` | `none` or `ollama` |
| `ai_endpoint` | `http://localhost:11434` | Ollama base URL (loopback only) |
| `ai_model` | `llama3.2` | Model name, e.g. `llama3.2`, `qwen2.5:7b` |
| `ai_timeout` | `120` | Request timeout, seconds |
| `ai_batch_size` | `8` | Reserved for batch inference |
| `ai_max_input_chars` | `12000` | Truncation applied to source text per request |
| `ai_prompt_version` | `1` | Versioned prompt; bumping it caches separately |

## Commands

```sh
# One message
python3 dispatch.py --archive ~/HB_Mail_Archive summarize run HASH

# Every archived message
python3 dispatch.py --archive ~/HB_Mail_Archive summarize run --all

# A whole conversation (thread)
python3 dispatch.py --archive ~/HB_Mail_Archive summarize run HASH --type thread

# Force regeneration even when the cached summary is current
python3 dispatch.py --archive ~/HB_Mail_Archive summarize run HASH --force

# View and remove summaries
python3 dispatch.py --archive ~/HB_Mail_Archive summarize list HASH
python3 dispatch.py --archive ~/HB_Mail_Archive summarize delete HASH
```

## How it works

- Message bodies are read through a **read-only** SQLite connection; the
  archive object is never opened for writing, and `archive.sqlite3` and raw
  EML are never modified.
- Summaries are written to `research.sqlite3` in the `summaries` table,
  keyed by `(message_hash, summary_type, model_name, prompt_version)`.
- Each summary stores an `input_digest` (SHA-256 of the exact text sent to
  the model). Re-running skips a summary only when the current input digest
  matches; if a thread gains a new message or reindexing changes extracted
  text, the cached summary is regenerated rather than silently reused.
- Results are committed one at a time, so an interrupted batch preserves
  completed work.

## Security boundaries

- The endpoint must be a loopback address (`localhost`, `127.0.0.1`, `::1`).
- HTTP redirects are refused and proxies are disabled, so archive text is
  not forwarded to a different host.
- Responses are bounded in size; request timeouts apply.
- The model receives only the selected message/thread text. It has no shell,
  filesystem, database-write, network, or tool access.
- A loopback endpoint does not by itself prove the inference backend is
  offline; for strict isolation run Ollama without internet access.

## Limitations

- Only one prompt version (`1`) exists today; the prompt is versioned so it
  can evolve without invalidating existing caches.
- Summaries are text generated by a model and may be wrong or incomplete.
  They are never exported as if they were the source record.
- `ai_batch_size` is stored but not yet used for batched model calls.
